## How I approach engineering

I care about software that is technically solid, operationally useful, and maintainable by real teams.

My default approach:

1. Understand the business process before designing the system.
2. Make the data model and edge cases explicit.
3. Prefer simple, traceable solutions over clever abstractions.
4. Document decisions so future work starts with context instead of archaeology.
5. Use AI as an engineering amplifier, not as a replacement for judgment.
